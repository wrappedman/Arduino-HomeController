از نصب تا اولین داشبوردِ قابل‌کنترل

این راهنما برای ESP32-S3-DevKitC-1 N16R8 و فریمور همین مخزن نوشته شده است. تصویرهای رابط زیر مستقیماً از اجرای همین نسخهٔ وب‌اپ در حالت شبیه‌سازی ثبت شده‌اند؛ در دستگاه واقعی نشان «SIMULATED DEMO» دیده نمی‌شود. شماتیک سیم‌کشی تصویر تولیدشده از برد واقعی نیست. هیچ آزمون فیزیکی در این محیط انجام نشده است.

شروع مرحله‌به‌مرحله ←اجرای برنامه
اول ایمنی: GPIO هیچ‌وقت به برق شهر، موتور یا بار پرجریان وصل نمی‌شود. ابتدا فقط مدار کم‌ولتاژِ آزمایشگاهی با منبع تغذیهٔ مناسب را امتحان کنید. رله باید ایزوله، دارای مشخصات مناسب و در حالت راه‌اندازی خاموش باشد. قطع‌کن و حفاظت الکتریکی مستقل لازم است. این نسخه هنوز تأییدیهٔ ایمنی/کاربری تجاری ندارد.
۰۱
از رایانهٔ خالی تا برد آماده

نصب نرم‌افزار، دریافت پروژه و انتقال دو تصویر

این دستورها در ترمینال رایانه اجرا می‌شوند؛ ESP32 آن‌ها را نمی‌فهمد. به رایانهٔ متصل به اینترنت، کابل USB داده‌دار و ESP32-S3-DevKitC-1 N16R8 با Flash شانزده مگابایت QIO و PSRAM هشت مگابایت OPI نیاز دارید. در نصب اولیه هیچ رله یا بار الکتریکی وصل نکنید. اگر مدل/حافظهٔ بردتان متفاوت است، این فریمور را فلش نکنید.

الف) کد پروژه را بگیرید و پوشهٔ صحیح را باز کنید

  1. به صفحهٔ همین شاخهٔ پروژه در GitHub بروید و Code → Download ZIP را بزنید؛ فایل را Extract کنید. نیازی به نصب Git ندارید.
  2. در پوشهٔ استخراج‌شده، platformio.ini را پیدا کنید. باید همان پوشه را در ترمینال باز کنید؛ نه پوشهٔ src یا data. در Windows داخل پوشه راست‌کلیک → Open in Terminal؛ در macOS/Linux با cd به آن بروید.
  3. در Windows دستور dir platformio.ini و در macOS/Linux دستور ls platformio.ini باید نام فایل را نشان دهد. اگر «file not found» آمد، در پوشهٔ اشتباه هستید.

این دستورها از کجا فایل‌ها را پیدا می‌کنند؟ PlatformIO از platformio.ini در پوشهٔ فعلی، نام محیط esp32-s3-devkitc-1-n16r8، مشخصات برد در boards/ و جدول Flash در partitions/ را می‌خواند. کد src/ به firmware.bin تبدیل می‌شود. همهٔ فایل‌های data/، شامل وب‌اپ، فونت وزیرمتن، تصاویر و همین راهنما، به littlefs.bin بسته‌بندی می‌شوند. برنامه بعداً تنظیمات شخصی را روی Flash در /config.json می‌نویسد، نه در پوشهٔ رایانه.

ب) Python و PlatformIO را نصب کنید

Windows 10/11: Python 3.11 را از python.org نصب کنید و گزینهٔ Add python.exe to PATH را بزنید؛ ترمینال را ببندید و دوباره در پوشهٔ پروژه باز کنید. خطوط زیر را در PowerShell اجرا کنید:

py -3.11 --version
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip platformio
$Pio = '.\.venv\Scripts\pio.exe'
& $Pio --version

اگر py شناخته نشد، Python/Launcher را نصب یا PATH را بررسی کنید. نیازی به فعال‌سازی محیط مجازی یا تغییر Execution Policy نیست. اگر PowerShell را بستید، بعداً خط $Pio = '.\.venv\Scripts\pio.exe' را دوباره بزنید.

macOS یا Linux: Python 3.11/3.12 را نصب کنید. در Ubuntu/Debian اگر ساخت محیط مجازی خطا داد، بستهٔ python3-venv را نصب کنید. در Terminal داخل پوشهٔ پروژه:

python3 --version
python3 -m venv .venv
./.venv/bin/python -m pip install --upgrade pip platformio
./.venv/bin/pio --version

دریافت ابزار Espressif و کتابخانه‌ها هنگام اولین ساخت به اینترنت و چند دقیقه زمان نیاز دارد. نسخهٔ PlatformIO باید در آخر چاپ شود؛ پوشهٔ .venv مخصوص رایانه است، نه برد.

پ) پورت برد را پیدا کنید

برد را با کابل USB داده‌دار وصل کنید؛ اگر برد دو سوکت دارد، ابتدا سوکت USB-to-UART را امتحان کنید. با برد جدا و وصل فهرست پورت‌ها را مقایسه کنید؛ نام جدید را یادداشت کنید:

# Windows PowerShell
& $Pio device list

# macOS / Linux
./.venv/bin/pio device list

مثال‌های زیر از COM5 در Windows و /dev/ttyUSB0 در Linux استفاده می‌کنند؛ پورت واقعی خودتان را جایگزین کنید. در macOS ممکن است /dev/cu.usbserial-... باشد. اگر پورت نیست، کابل/سوکت را عوض کنید و در صورت نیاز درایور USB-UART متناسب با چیپ روی برد را نصب کنید. در Linux خطای Permission denied به مجوز گروه پورت (معمولاً dialout، گاهی uucp) مربوط است؛ بعد از اصلاح مجوز از نشست خارج و دوباره وارد شوید، نه اینکه PlatformIO را با sudo اجرا کنید.

ت) برنامه و سپس وب‌اپ را آپلود کنید

در همان ترمینال، فقط دستورهای سیستم‌عامل خودتان را اجرا کنید. خط run تنها کامپایل می‌کند و چیزی به برد نمی‌فرستد. upload فریمور و فایل‌های بوت/پارتیشن را می‌نویسد. buildfs از تمام فایل‌های data/ تصویر وب‌اپ می‌سازد و uploadfs آن را به پارتیشن LittleFS منتقل می‌کند. نصب اولیه به هر دو آپلود نیاز دارد:

# Windows PowerShell — replace COM5 with YOUR port
& $Pio run -e esp32-s3-devkitc-1-n16r8
& $Pio run -e esp32-s3-devkitc-1-n16r8 -t upload --upload-port COM5
& $Pio run -e esp32-s3-devkitc-1-n16r8 -t buildfs
& $Pio run -e esp32-s3-devkitc-1-n16r8 -t uploadfs --upload-port COM5
& $Pio device monitor -p COM5 -b 115200
# macOS / Linux — replace /dev/ttyUSB0 with YOUR port
./.venv/bin/pio run -e esp32-s3-devkitc-1-n16r8
./.venv/bin/pio run -e esp32-s3-devkitc-1-n16r8 -t upload --upload-port /dev/ttyUSB0
./.venv/bin/pio run -e esp32-s3-devkitc-1-n16r8 -t buildfs
./.venv/bin/pio run -e esp32-s3-devkitc-1-n16r8 -t uploadfs --upload-port /dev/ttyUSB0
./.venv/bin/pio device monitor -p /dev/ttyUSB0 -b 115200

بعد از هر مرحله SUCCESS را ببینید؛ Serial Monitor را پس از هر دو آپلود باز کنید چون پورت نمی‌تواند همزمان توسط آن و آپلود اشغال شود. حالا EN/RESET را بدون BOOT بزنید تا پیام‌های بوت را ببینید؛ خروج از Monitor با Ctrl+C است. اگر صفحهٔ وب 404 بود، احتمالاً uploadfs انجام نشده است.

هشدار به‌روزرسانی: اگر برد قبلاً تنظیم شده، قبل از اجرای دوبارهٔ uploadfs از System Settings → Download backup نسخهٔ پشتیبان بگیرید؛ این آپلود ممکن است /config.json شامل دستگاه‌ها و داشبورد را پاک کند. برای فلش اولیه نیازی به دستور erase_flash نیست. فایل پشتیبان شامل رمز مدیر و وای‌فای نیست.

اگر آپلود روی Connecting... ماند، پورت و کابل را بررسی کنید و Monitor را ببندید؛ در صورت نیاز برای ورود به حالت فلش BOOT را نگه دارید، EN را یک بار بزنید، BOOT را رها کنید و آپلود را تکرار کنید. نگه‌داشتن BOOT هنگام روشن‌کردن اجرای برنامه را متوقف می‌کند؛ بازیابی شبکه با نگه‌داشتن BOOT پنج ثانیه بعد از اجرای برنامه فرق دارد. نسخهٔ کامل قابل مطالعه پیش از نصب، همراه عیب‌یابی، در GitHub هم قرار دارد.

✓ نتیجهٔ مورد انتظار: پیام SHAP ... ready و SETUP AP: SmartHome-Setup-XXXX PASSWORD: ... در سریال. رمز شبکهٔ راه‌اندازی را خصوصی نگه دارید.

۰۲
سخت‌افزار آزمایشگاهی

یک رلهٔ ایزولهٔ کم‌ولتاژ را متصل کنید

برای آزمایش این راهنما GPIO14 را به ورودی منطقی رلهٔ سازگار وصل کنید. GPIO8/9 برای DS3231 و GPIO10 تا 13 برای ماژول microSD سه‌ولت‌وسه رزرو هستند. ورودی‌ها را از نظر ولتاژ و حفاظت بررسی کنید. وضعیت خاموشِ رله را هنگام روشن‌شدن، ریست و قطع برق با مدار سخت‌افزاری تضمین کنید.

✓ نتیجهٔ مورد انتظار: با راه‌اندازی برد، رله بدون فرمان روشن نشود؛ ابتدا بدون بار خطرناک بررسی کنید.

۰۳
ویزارد تنظیمات

به شبکهٔ راه‌اندازی وصل شوید

  1. در سریال، SmartHome-Setup-XXXX و گذرواژهٔ تصادفی اختصاصی همان برد را بخوانید.
  2. با گوشی یا لپ‌تاپ به همان شبکه وصل شوید.
  3. در مرورگر آدرس http://192.168.4.1 را باز کنید و Start configuration را بزنید.

✓ نتیجهٔ مورد انتظار: ویزارد پنج‌مرحله‌ای باز شود. هیچ گذرواژهٔ مدیر پیش‌فرضی وجود ندارد.

۰۴
شبکهٔ محلی

وای‌فای خانه را وارد کنید

در مرحلهٔ دوم روی Scan nearby networks بزنید یا SSID را دستی تایپ کنید؛ گذرواژهٔ همان شبکهٔ ۲٫۴ گیگاهرتز را وارد کنید. این نسخه اتصال IP ثابت را پیاده‌سازی نکرده است. پس از اتمام تنظیمات، دستگاه ریست می‌شود و IP اختصاص‌یافته را در سریال با SHAP LAN IP: نشان می‌دهد.

✓ نتیجهٔ مورد انتظار: SSID و گذرواژه ثبت شوند و در پایان آدرس IP دستگاه در شبکهٔ محلی مشخص شود.

۰۵
امنیت و زمان

حساب مدیر و نام خانه را بسازید

نام کاربری حداقل سه حرف و گذرواژهٔ اختصاصی حداقل ده نویسه تعیین کنید؛ تکرار را یکسان وارد کنید. در گام چهارم نام خانه و منطقهٔ زمانی را با قالب POSIX تعیین کنید (برای آزمون UTC0؛ برای تهران بدون تغییر ساعت تابستانی IRST-3:30). برای اجرای زمان‌بندی بعد از قطع برق، DS3231 به‌کار ببرید؛ وگرنه بعد از هر روشن‌کردن از Settings → Sync browser time ساعت را همگام کنید.

✓ نتیجهٔ مورد انتظار: پس از Finish setup & restart، برد به وای‌فای وصل و IP در سریال چاپ شود.

۰۶
ورود

از آدرس IP دستگاه وارد شوید

به وای‌فای خانه برگردید؛ در مرورگر http://IP-دستگاه را باز کنید و با حسابی که ساختید وارد شوید. این نسخه از HTTP استفاده می‌کند؛ بنابراین آن را فقط در شبکهٔ محلیِ ایزوله و مورد اعتماد اجرا کنید و هرگز پورت وب را به اینترنت باز نکنید.

✓ نتیجهٔ مورد انتظار: صفحهٔ Overview باز شود و نشان اتصال محلی نمایش داده شود (در نسخهٔ نمایشی: SIMULATED DEMO).

۰۷
ثبت سخت‌افزار

رلهٔ نمونه را در Devices اضافه کنید

  1. از منوی Devices روی Add device بزنید.
  2. نامی مانند Hallway relay، نوع Relay output و GPIO برابر 14 انتخاب کنید.
  3. اگر ورودی ماژول با صفر فعال می‌شود Active-low output را روشن کنید؛ دربارهٔ نوع رله حدس نزنید.
  4. برای خروجی حساس، زمان روشن‌بودن بیشینه و گروه interlock را تنظیم کنید؛ Create device را بزنید.

✓ نتیجهٔ مورد انتظار: رله در فهرست Devices دیده شود؛ فرمان Test فقط پس از بازبینی سخت‌افزار.

۰۸
اعتبارسنجی پایه

انتساب GPIO14 را کنترل کنید

به Hardware & GPIO بروید و روی 14 کلیک کنید. در Pin Inspector باید Assigned device: Hallway relay را ببینید. firmware انتساب تکراری، پایهٔ رزروشده و ADC نامعتبر را رد می‌کند؛ نقشهٔ گرافیکی برای ارزیابی بصری است و جای pinout رسمی برد را نمی‌گیرد.

✓ نتیجهٔ مورد انتظار: 14 «Assigned» و نام رله در سمت راست نمایش داده شود.

۰۹
طراحی بصری

ویجت بسازید و دستگاه را به آن نگاشت کنید

  1. از Dashboard Designer یک ON/OFF toggle را کلیک یا به بوم بکشید.
  2. ویجت را انتخاب کنید؛ در Properties Inspector عنوان و Mapped device = Hallway relay را تنظیم کنید.
  3. عرض و ارتفاع را از منوها تغییر دهید؛ برای جابه‌جایی از درگ یا دکمه‌های جهت استفاده کنید.
  4. Save layout پیش‌نویس را ذخیره می‌کند؛ Publish dashboard آن را در Overview نمایش می‌دهد. برای ویجت بدون دستگاه نیز عنوان نمایش داده می‌شود اما کنترل غیرفعال است.

✓ نتیجهٔ مورد انتظار: ویجت در بوم قابل انتخاب باشد و عنوان/نگاشت پس از تغییر به‌روز شود.

۱۰
انتشار و آزمایش

ویجت را در Overview ببینید و امتحان کنید

روی Publish dashboard بزنید. صفحهٔ Overview باز و به ویجت تازه اسکرول می‌شود. ویجت جدید، عنوان، مقدار یا کلیدِ دستگاه نگاشت‌شده را نشان می‌دهد؛ با کلیک بر کلیدِ ویجتِ رله، وضعیت تغییر می‌کند. صفحه را Refresh کنید تا ماندگاری چیدمان را کنترل کنید. در حالت نمایشی داده‌ها فقط در مرورگر ذخیره می‌شوند؛ روی دستگاه واقعی تنظیمات در LittleFS هستند.

✓ نتیجهٔ مورد انتظار: ویجت بعد از Refresh هم باقی بماند و کلید نگاشت‌شده فرمان را به دستگاه منطقی بفرستد.

۱۱
اجرای مستقل از مرورگر

یک قانون سادهٔ WHEN / IF / THEN بسازید

در Automations → Create automation یک حسگر ثبت‌شده، عملگر Equals/Above/Below، شرط اختیاری، رلهٔ مقصد و عمل ON/OFF/Toggle را انتخاب کنید. تأخیر حداکثر ۳۶۰۰ ثانیه است. در حالت سخت‌افزاری، موتور قوانین در حلقهٔ firmware اجرا می‌شود و به بازبودن مرورگر وابسته نیست؛ در شبیه‌ساز اجرای قانون فقط داخل مرورگر است.

✓ نتیجهٔ مورد انتظار: قانون در فهرست ظاهر شود؛ برای تأیید اجرای آفلاین، مرورگر را ببندید و روی برد واقعی آزمون کنید.

۱۲
نگهداری

پشتیبان بگیرید، ساعت را تنظیم کنید و وضعیت را بررسی کنید

در System Settings از Download backup برای دریافت تنظیمات بدون اطلاعات مدیر/وای‌فای، از Sync browser time برای تنظیم ساعت و از Export diagnostics برای بررسی حافظه استفاده کنید. Restore را فقط با فایل مربوط به همین برد انجام دهید. OTA امضای دیجیتال ندارد و آزمایشی است؛ از فایل ناشناس استفاده نکنید. microSD اختیاری است؛ بدون آن تاریخچه فقط تا سقف بافر RAM در دسترس است.

بازیابی شبکه: اگر آدرس دستگاه در دسترس نبود، ابتدا اجازه دهید برد کاملاً بالا بیاید؛ سپس دکمهٔ BOOT (GPIO0) را پنج ثانیه نگه دارید. فقط اطلاعات وای‌فای پاک و برد با شبکهٔ راه‌اندازی ریست می‌شود؛ حساب مدیر و دستگاه‌ها حفظ می‌شوند. دکمه را همزمان با روشن‌کردن یا ریست نگه ندارید: GPIO0 پایهٔ حالت بوت است و برد ممکن است وارد حالت دانلود شود. محل فیزیکی دکمه را از روی برچسب برد خود تشخیص دهید.

✓ نتیجهٔ مورد انتظار: فایل پشتیبان دانلود شود و تنظیمات پس از یک ریست کنترل‌شده باقی بمانند.
